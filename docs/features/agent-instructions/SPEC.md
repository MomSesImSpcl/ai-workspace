# Agent instructions browser

[Summary](SUMMARY.md). Decision: [ADR 0022](../../architecture/decisions/0022-agent-instructions-catalog.md).

The user wants to find every rule the workspace gives agents, read it, and understand where and why it is used, before deciding how editing should work (user, 2026-10-23). Iteration one is read only.

## Requirements

- **agent-instructions-001 — Development only (built 2026-10-23; superseded by agent-instructions-006 on 2026-11-23):** The **Agent instructions** tab in Settings and its data are available only while the app runs from a git checkout, the condition Update and restart also needs. Elsewhere the tab is not shown and the data request is refused. Whether a release shows it is not decided.
- **agent-instructions-002 — Complete catalog (built 2026-10-23):** The tab lists every agent-facing text the workspace writes: role notes in the system or developer prompt, text it puts into messages (earlier conversation, unfinished-turn markers, continuations, context from an earlier task), the descriptions and parameter descriptions of its workspace tools, and tool replies and refusals that tell the agent what to do next. Plain validation errors that only name a bad value are left out. Entries are grouped by purpose: role notes, messages and continuation, workspace tools, tool replies and refusals.
- **agent-instructions-003 — Find (built 2026-10-23):** A search field filters by title, purpose, text and id; a filter narrows to one role (Chat, Orchestrator, Implementer, Subtask). Entries name roles, not agents: every agent gets the same instructions ([ADR 0023](../../architecture/decisions/0023-one-agent-interface.md)); where an agent still misses an entry, the entry shows that gap until the unified interface removes it. Each list entry shows its name and a short purpose; groups are sorted A–Z.
- **agent-instructions-004 — Read (built 2026-10-23):** The selected entry shows its purpose, its full text with formatting kept, other forms of the same message with when each is used, tool parameters, the roles that get it, any agent still missing it, when it is included, how it reaches the agent, and its source file and definition. Placeholders such as `{branch}` are marked and explained as values filled in when the text is sent, never as actual values. The text MUST match what the code sends: an entry shows the instruction registry's text, the only place it is written ([agent-interface-007](../agent-interface/SPEC.md#requirements), since 2026-11-23), and where the code sends it.
- **agent-instructions-005 — Outside sources (built 2026-10-23; removed 2026-11-23 by the user: they can be neither read nor edited here, so the tab lists only workspace instructions; the role Instructions fields move into the tab by 011):** Sources the workspace does not write are listed separately: the Instructions fields of Settings → Agents (shown in full), the workspace folder's and the user's global rule files (path and whether the file exists, opened in its folder), project rule files, the agents' own system prompts, Codex memories and other agent extensions. Each is labelled with what can be inspected; text the workspace cannot read is marked as such, and the tab MUST NOT suggest it contains provider instructions it does not have.

### Defaults and overrides (specified 2026-11-23, user; [ADR 0025](../../architecture/decisions/0025-instruction-overrides.md))

The tab becomes the place where every default instruction is kept and where the user can change any of them, with the default always kept as the fallback.

- **agent-instructions-006 — Every build (not started):** The tab and its data are available in released builds as well as from a checkout; this supersedes 001.
- **agent-instructions-007 — Simpler entry view (built 2026-11-23):** Each entry shows its title, one description under it (what it is for and when it is sent, a single field of the registry entry, written once there), its text and other forms, its tool parameters and placeholders, and its id in small type for search. "Used by", "When included", "How it reaches the agent" and "Source" are not shown. An entry that some agents do not get because they lack a capability shows that in one line (agent-interface-005).
- **agent-instructions-008 — Default, Override, Append (not started):** Every text form of an entry (the main text, each variant, each tool parameter description) has a mode: Default sends the registry text; Override sends only the user's text, which may say anything, including the opposite of the default, and the user is responsible for it still working; Append sends the default followed by the user's text. Behavior the workspace enforces in code is not changed by an override. A changed entry is marked in the list, and one action returns it to Default.
- **agent-instructions-009 — Placeholders in user text (not started):** Override and Append text may use the entry's placeholders, filled in like the default's. A placeholder the entry does not have is refused on save with the list of available ones; leaving placeholders out is allowed, and the editor shows which ones the default uses.
- **agent-instructions-010 — Storage and fallback (not started):** Modes and user texts are stored in the workspace settings, carried by export and import ([workspace-transfer](../workspace-transfer/SUMMARY.md)), and apply to every agent from its next start (role notes, tool descriptions) or next send (messages, replies). The registry text is never changed; app updates keep updating defaults, and an entry in Override MAY say that its default changed since the override was saved.
- **agent-instructions-011 — Your instructions per role (not started):** The Instructions fields of Settings → Agents move into this tab as one "Your instructions" entry per role (Chat, Orchestrator, Implementer) with an empty default and Append, sent where the fields are sent today; existing field text is migrated, and the fields are removed from Settings → Agents.

## Non-goals and open decisions
- Scope (user, 2026-11-23): the tab lists all fixed text the workspace sends between agents and every rule that shapes it, including what is added around the orchestrator's own messages. What a model writes (a task's goal, a reply) differs each time and is shown per chat and task, not here.

- Deferred: a preview of the exact instructions one session received, which needs runtime tracing.
- Order (user, 2026-11-23): 007 first, then [agent-interface-008](../agent-interface/SPEC.md#requirements) (rules into code), then 006 and 008–011, so users do not override texts that are about to become code.

## Acceptance evidence

- `app/test/instructions.test.ts`: copies match their sources, every workspace tool and parameter description is listed, every placeholder is explained, outside sources carry no provider text, the development gate.
- Browser check of the tab against a UI server on throwaway storage ([history](../../history/2026-10-23-05-agent-instructions-browser/SUMMARY.md)).
