# Developing the workspace inside itself

[Shared principles](../../PRINCIPLES.md) apply.

[Dependencies and related features](SUMMARY.md). Read affected contract sections when implementing.

The user plans to move development of this repository into the workspace as soon as it is ready. Today that happens in external agent apps that create a Git worktree per session. This feature keeps that safety when the workspace edits its own code while running.

## Requirements

- **selfdev-001 — Worktree per change (built 2026-10-19, [ADR 0014](../../architecture/decisions/0014-worktree-per-session.md)):** A session or task that changes the workspace's own repository MUST work in its own Git worktree and branch from the current `main`, never in the checkout the running app is started from. The workspace creates the worktree and starts the session in it, so isolation never depends on the agent remembering it. Sync with `main`, merging and cleanup of merged worktrees are the agent's work through its own Git tools; as a safety net (user, 2026-10-19) the workspace removes merged branches without uncommitted changes and without a running agent at start and once a day, archives the chats of any removed branch (read only, under "Show archived"), never removes unmerged work on its own, and lists every branch of the app project with its state, size, folder and a Remove… that asks before losing work in Settings → General ([vcs-011](../version-control/SPEC.md)); the [version-control](../version-control/SPEC.md) UI MAY show them but is not needed (user, 2026-10-19). A worktree another active session uses is never removed, and the workspace notices when a session's worktree is gone. Built: the app adds the repository it runs from as a project at every start (first in the list, no menu), and only that project's sessions get a worktree in workspace storage on branch `aiws/<session id>` from the checkout's HEAD, made at its first turn with a notice in the chat; a chat's tasks and their subtasks share it; a worktree gone after that stops the session with an error. A new chat starts only after the user names a new worktree (the name is also its branch: letters, digits, `.`, `_`, `-`; empty, invalid or taken names are refused with a message) or picks an existing workspace-made one to continue, both left in the Send row; the sessions list groups the project's chats under one heading per worktree (2026-10-19). A new worktree gets its npm dependencies (`npm ci` where a `package-lock.json` is, run by the app outside the agent's sandbox) before the agent starts, with notices in the chat; a failed install is reported and does not stop the session ([#26](https://github.com/MomSesImSpcl/ai-workspace/issues/26), 2026-10-20).
- **selfdev-002 — Running instance untouched (built 2026-10-19, [ADR 0015](../../architecture/decisions/0015-write-guard.md)):** Agent edits, installs and builds MUST NOT change the files, dependencies or storage of the running instance. Tool-broker path checks enforce this for the agent's tools; it is not left to model instructions ([architecture 3.3](../../ARCHITECTURE.md#33-data-isolation-and-data-classification)). Built: every session and task is guarded against writes to the app's checkout and the workspace's storage outside its own folder; Claude Code through a `PreToolUse` hook that also holds in bypass mode, Codex by declining such approval requests and running worktree sessions in its `workspace-write` sandbox without approvals instead of full access, with the checkout's `.git` parts a commit needs writable (tested on Windows with both real agents 2026-10-20). Commands that only read pass; every blocked write is shown in the chat with the command or file. Shell commands are checked by the paths they name, so a path computed at run time is not seen ([#18](https://github.com/MomSesImSpcl/ai-workspace/issues/18)).
- **selfdev-003 — Verify in the worktree (built 2026-10-20 as a workspace rule, [ADR 0017](../../architecture/decisions/0017-merge-through-workspace.md)):** Before review, the agent runs the repository's own checks in the worktree (`npm run typecheck` and `npm test` in `app/` today) and reports the results in the chat, where they stay with the session or task as evidence. For UI changes, [ui-verification](../ui-verification/SPEC.md) against an instance started from the worktree MAY add screenshots.
- **selfdev-004 — Review before applying:** Merging into `main` needs the user's approval in the chat, under the existing approval and permission rules ([ADR 0004](../../architecture/decisions/0004-agent-native-permissions.md)); no agent merges its own change into the running app unasked. The agent commits and pushes its branch; changes reach `main` only through a pull request ([ADR 0016](../../architecture/decisions/0016-main-ruleset.md)). Built 2026-10-20 ([ADR 0017](../../architecture/decisions/0017-merge-through-workspace.md)): the agent calls the workspace tool `request_merge` with its check results; it opens the pull request if needed, shows one approval card, and on Allow the app squash-merges it. Agents cannot run `gh pr merge` themselves (guard; no `gh` login in Codex's worktree shells; limits in [#31](https://github.com/MomSesImSpcl/ai-workspace/issues/31)).
- **selfdev-005 — Apply by restart (built 2026-10-20, [ADR 0018](../../architecture/decisions/0018-restart-and-fallback.md)):** After merge, the running app offers a restart onto the new code. Sessions and tasks MUST survive it: running turns are either finished first or recorded as interrupted and resumable ([sessions](../sessions/SPEC.md), [task-runtime](../task-runtime/SPEC.md)). The session that requested the restart continues afterwards. Built: when `origin/main` has commits the app's checkout lacks (checked at most every 5 minutes), the toolbar shows "Update and restart": a fast-forward of the checkout (refused on another branch, with uncommitted changes in `app/` or local commits), changed dependencies installed, then a restart. Session and task hosts are detached and keep running through it; they keep their old code until they end ([#37](https://github.com/MomSesImSpcl/ai-workspace/issues/37)).
- **selfdev-006 — Fall back (built 2026-10-20, [ADR 0018](../../architecture/decisions/0018-restart-and-fallback.md)):** If the new version fails to start or fails its startup check, the user MUST be able to start the last working version (the last `main` commit that passed its startup check; user, 2026-10-20) without manual Git work, and see why the new one failed. Storage format changes need a migration that the previous version tolerates or a backup taken before the restart ([workspace-transfer](../workspace-transfer/SPEC.md)); agreed 2026-10-20: a backup only before a version with a storage migration, not built ([#37](https://github.com/MomSesImSpcl/ai-workspace/issues/37)). Built: the startup check is basic (user, 2026-10-20): the UI server starts and the page reads projects, tasks and sessions within 60 s. A restart keeps the old instance until the new one passes; on a failure the old one, or a failed cold start itself, shows why and offers the last working version, a copy kept in workspace storage with its own dependencies and Electron.
- **selfdev-007 — Not only this repository (deferred 2026-10-19 by the user: only the app project works in worktrees, ADR 0014):** The same flow applies to any project whose running app the user develops in the workspace; this workspace is the first case.

Agent dependence: worktree work, approvals and interruption rely on the [integration matrix](../../INTEGRATIONS.md) rows "Own tools, settings and permissions (ADR 0004)", "Relay "ask" prompts as approval cards" and "Stop a turn"; agents without approval relay fall back to the workspace approval check before merge.

## Acceptance evidence

- From a workspace session, an agent changes a UI label in a new worktree; typecheck, tests and a UI check pass there; the running app is unchanged until the user approves the merge.
- After approval and restart, the app runs the new code and the session that made the change continues with its history.
- A change that breaks startup leads to an offer to start the previous version, with the error shown.

## Non-goals and open decisions

- No automatic merge or deploy without approval; no hot code swap of the running process.
- Decided 2026-10-19 ([ADR 0014](../../architecture/decisions/0014-worktree-per-session.md)): worktrees live in workspace storage, only the app project uses them, a chat's tasks share its worktree.
- Open: contents of the startup check; whether the previous version runs from a kept worktree or a fresh checkout of the previous commit.
- Using the workspace on its own repository after the core was proposed earlier and is still not an agreed delivery order ([proposal record](../../history/2026-10-16-00-imported-progress-snapshot/DETAILS.md#proposed-not-yet-agreed)).
