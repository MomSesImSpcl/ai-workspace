# Video research, style guides and YouTube production

[Shared principles](../../PRINCIPLES.md) apply.

[Dependencies and related features](SUMMARY.md). Read affected contract sections when implementing.

- Research topics and competitor/reference videos from legally/technically accessible sources. Ingest authorized transcripts, video keyframes, timestamps, audio, metadata and supplied project/creator references.
- Analyze separately: language style, vocabulary, sentence length, explanations, comedic placement/callbacks, hooks, transitions, pacing, storytelling, viewer address and factual rigor; for visual editing, analyze cuts, timing, framing, B-roll, graphics, music and sound, not only transcripts.
- Build user-owned **style guides** and examples with provenance, e.g. `VIDEO_STYLE.md`, `HUMOR.md`, `SCRIPT_STRUCTURE.md`, `EDITING_STYLE.md`. Learn desired principles without copying protected scripts, voices or distinctive expression verbatim.
- Use project docs, Git history and development milestones to propose truthful devlog outlines and scripts. Have source/fact checking and human review.
- Optional production tools: transcription, speech/voice generation where authorized, shot/asset logging, B-roll identification, rough-cut assembly using FFmpeg/approved NLE tooling, thumbnails, short-form story planning and publication checklist.
- Video editors see only permitted video repos and sanitized game knowledge, not the entire game's private source by default.
- Reuse the same Task Runtime, artifact system, model roles, skills and permissions as all other domains; do not create a separate YouTube workspace.
