# Desktop workspace and Task Center

[Shared principles](../../PRINCIPLES.md) apply.

[Dependencies and related features](SUMMARY.md). Read affected contract sections when implementing.

## 2.1 Desktop client

- Full workspace interface with project selection, interactive AI sessions, task list, task details, artifacts, model selection, search, relevant files, logs and local runner management.
- Support native desktop integrations as needed: dialogs, notifications, clipboard, deep links, filesystem/file associations, credential storage and process status.
- The client does not own long-running task state. Closing it must not automatically cancel delegated tasks.
- Permit multiple interactive conversations and quick transitions between a conversation and its delegated tasks.
- Include a **Task Center** showing `queued`, `waiting-for-runner`, `running`, `paused`, `blocked/approval-needed`, `failed`, `cancelled` and `completed`. Do not invent numerical progress percentages when only step/status progress is known; show verified steps and logs instead.
- Task controls: the Task Center is a view, not where work is started or steered ([ADR 0010](../../architecture/decisions/0010-tasks-started-from-chat.md)). Per task it MUST show the prompt that started it and the session it belongs to, what it is working on now, its current step and its token consumption against the budget, and MUST offer **Cancel**, plus **Pause** and **Resume** ([runtime-006](../task-runtime/SPEC.md#47-agent-native-tasks)). Starting tasks, approvals, replies, resume and the other controls (priority, checkpoint, retry, clone, artifacts, review, model override, merge/accept) belong to the chat that started the task or to the orchestrator. The stopgap start form, approvals, reply and resume were removed with sessions-002; a task started outside a chat (CLI) still shows its pending approvals in the Task Center, since it has no chat.
- **desktop-001 — Settings overlay with tabs (user, 2026-10-19):** Settings MUST open as an overlay on top of the interface, not as a column that narrows it. It MUST be anchored at the tool rail and cover everything right of the sessions column, which stays visible. The covered area MUST get a light backdrop; Esc or a click on the backdrop closes Settings. Settings MUST be split into tabs, placed on the right of the panel so they stay put when its width changes: **General** (workspace folder, workspace storage), **Agents** and **Agent setup**. The last open tab MUST be restored when Settings opens again, also after a restart.
  - **General:** on first start from a source checkout, the workspace folder is the repository the app runs from until the user picks another; a packaged app starts without one.
  - **Agents** ([ADR 0013](../../architecture/decisions/0013-three-roles.md)): one block per role in the order Chat, Orchestrator, Implementer (role `Implementation`), each with Agent, Default model and Default effort, picked from the agent's catalog ([onboarding-008](../onboarding/SPEC.md#requirements)); switching a role to another agent restores that role's last model, effort and permission for that agent (defaults the first time, or for a choice the agent no longer offers); a new model resets effort. The Implementer also has **Default permission**, the agent's own permission modes, used for new tasks unless a chat picks another mode; a mode that skips every check asks for confirmation. Only runnable agents are offered. Each role has an optional instructions field, added to that role's agent from its next start: plain chats, orchestrator chats, tasks.
  - **Agent setup:** the panel widens to fit one column per agent, at most up to the sessions column. Its content keeps to the right, where the other tabs show theirs: the top part at the normal panel width, the agent columns packed against the right edge. Each agent is one column with its own vertical scroll and its name centred above it, staying visible while the list scrolls, with a search field and the column titles (Item and the roles, with a faint line under them) below it. Items are grouped (Built-in, Plugins, MCP servers and connectors, Skills, Hooks) under titles with a faint line, sorted A–Z; search matches titles and descriptions and keeps the groups, hiding empty ones. Descriptions are tooltips, except the names inside Standalone skills and Your hooks, which stay visible; each switch shows its full value as a tooltip. An item with a known folder (a Claude Code plugin, an MCP server started from a program path, the settings holding your hooks) has its name as a button with a folder icon: a known file (the server's program, `SKILL.md`, the settings file, `CLAUDE.md`) is shown selected in its folder, never opened or run; otherwise the folder opens; each standalone skill is such a button for its own folder, and each global-rules switch has one on its left for the global rules folder; the columns scroll sideways when they do not fit. New settings join the tab they fit; a new tab (for example Permissions for [permissions-001](../agent-permissions/SPEC.md)) is added when its feature is built.
- **desktop-002 — Accent colour (user, 2026-10-19; specified, not built):** Settings → **General** MUST offer an accent colour choice: a row of about six preset swatches, the current warm orange (`#d97757`) first and the default, plus **Custom…**, which opens a colour picker for any colour. The app MUST derive the whole accent token family (`--accent`, `--accent-bright`, `--accent-strong`, `--accent-dim`, `--accent-edge`, `--on-accent`) from the one chosen colour; nothing outside these tokens may change, so components keep using only the `--accent*` tokens. Derived colours MUST stay readable: `--on-accent` text on `--accent-strong` MUST reach WCAG AA contrast (4.5:1), and `--accent` used as text or icon on the panel background MUST reach 3:1; when a custom colour misses this, the derived shades are adjusted in lightness (hue kept) until it passes, and the picker shows the adjusted result. Presets MUST pass without adjustment. The choice is a UI preference stored with the other UI prefs (`/api/prefs`), not in workspace or project settings, and is restored after a restart. It MUST apply immediately to the open window without restart or reload, and **Reset** returns to the default. Non-goals: full themes, light/dark switching, per-project colours.
