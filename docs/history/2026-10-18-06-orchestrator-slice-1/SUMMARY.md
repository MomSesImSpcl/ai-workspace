# Orchestrator slice 1: the orchestrator chat works through tasks

A new chat session starts as the orchestrator (Orchestration role). Every change request becomes a task, a correction goes to that task with `reply_task`, and a question is answered directly ([ADR 0011](../../architecture/decisions/0011-orchestrator-works-through-tasks.md), orchestrator-006). The orchestrator picks each task's agent, model and effort with a reason, and the user can change them (orchestrator-004). Tasks run uncapped unless the cap switch next to the chat box is on. Tasks have Pause and Resume (runtime-006). The workspace blocks the orchestrator's own edit and command tools by role, not by agent. Tests 45/45; real Codex orchestrator with a Claude Code task.
