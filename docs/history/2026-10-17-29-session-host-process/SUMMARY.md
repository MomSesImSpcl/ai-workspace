# One Claude Code process per session

Fixes [#15](https://github.com/MomSesImSpcl/ai-workspace/issues/15) as decided in [ADR 0008](../../architecture/decisions/0008-session-host-process.md): a Claude Code session now runs in one long-lived `claude -p --input-format stream-json` process fed one message per turn by a detached session host, so plugin and hook state (for example cache-tax's resend) survives between turns. One host per session (exclusive lock), idle end after 30 minutes, Stop through Claude Code's own interrupt, a turn left by a dead host recorded as interrupted. Codex keeps one process per turn.

Files: `app/src/adapters/claude-code.ts` (`ClaudeProcess`), `app/src/turn.ts` (`hostSession`, `runSession`, `runTurn` with the lock), `app/src/sessions.ts` (`acquireRunner`, `releaseRunner`, `markStarting`, `sessionWorking`), `app/src/approval-server.ts` (turn from the log), `app/src/ui.ts`, `app/src/cli.ts`; tests `app/test/host.test.ts` with `app/test/fake-claude.mjs`.

Checks: probe of the real CLI (two turns in one process, interrupt keeps the process, stdin end exits 0). `npm test` 40/40 (one process for all turns and idle end; Stop then continue in the same process; orphaned turn marked interrupted, not re-run). Real run through the app API with the user's own Claude setup: turns 1-6 answered by one Claude Code process (same pid); Stop mid-reply ended the turn in 326 ms and the process answered the next message; killing the host mid-reply left the turn interrupted and the next message started a new host with `--resume` and got its answer. Not reproduced: an actual cold-cache drop by cache-tax (needs the cache cold for over an hour); covered by the plugin's own resend logic now running in one process. Branch `claude/chat-sessions-per-project-f82af3`.
