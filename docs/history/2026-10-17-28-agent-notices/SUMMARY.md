# Agent notices in the chat (dropped prompts)

Bug report: messages got no reply and no error. Cause: the user's cache-tax plugin drops a prompt sent to a cold prompt cache (`system`/`informational` event, `prevent_continuation`), and the workspace ignored that event, so the turn ended as done with no text. Sessions now record such events as `notice` events and show them in the turn, stating that the agent's own setup stopped the message. The plugin's "send it again" cannot work with one agent process per turn, because its memory of the first drop is gone in the next process: known limit [#15](https://github.com/MomSesImSpcl/ai-workspace/issues/15), workaround `/cache-tax guard warn`, fix a long-lived process per session. Evidence: replay of the resumed turn showed the drop notice and an empty result. Tests 37/37 (parser test for the notice). Branch `claude/chat-sessions-per-project-f82af3`.
